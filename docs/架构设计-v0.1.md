# MacToolbox 架构设计 v0.1

> 目标：一个 macOS 原生的「命令行工具箱外壳」。GUI 只负责输入、编排、进度、检查点与交付；真正的能力来自本机已安装的 CLI 与随工具附带的脚本。新增功能不重新设计架构，只新增一个工具包。

- 文档日期：2026-10-18
- 状态：设计稿（未写代码）
- 首个验证场景：本地视频字幕生成（见 `本地视频字幕生成方案_v1.0.md`）

---

## 0. 结论先行

| 决策 | 结论 |
|---|---|
| GUI 技术 | **SwiftUI + 少量 AppKit**，原生单进程，不引入 WebView / Node / Rust 运行时 |
| 分发形态 | **非沙盒**、Developer ID 签名 + 公证；不走 Mac App Store |
| 扩展方式 | **声明式工具包（manifest + 脚本）为主，语言无关的 Tool Protocol 为辅，原生模块为少数例外** |
| 后端边界 | App 内置执行引擎；工具 = 外部 CLI + 工具自带脚本；不把 ffmpeg/whisper 打进 App |
| 编排模型 | 固定原语（exec / review / file / assert），**不做通用工作流 DSL** |
| 长任务 | 任务与工件落盘、状态机、可取消、可断点续跑、GPU 资源串行 |
| 启动指标 | 冷启动 P50 < 400 ms，空闲内存 60–90 MB，App 本体 < 20 MB，空闲 0 后台进程 |

一句话架构：**原生外壳 + 通用执行引擎 + 声明式工具包 + 少量固定原语 + 落盘任务状态**。

## 1. 需求与约束

### 1.1 功能需求

1. 一个统一入口，按类别浏览、搜索、运行各类「工具」。
2. 工具可以是一次 CLI 调用（视频压缩），也可以是带人工检查点的多步流水线（字幕生成）。
3. 工具能调用本机安装的 CLI（ffmpeg / whisper-cli / python3 / brew 安装物）。
4. 能复用已有的 Python/Bash 脚本，不要求改写成 Swift。
5. 新增工具的成本要低：理想情况下只写 manifest + 一个脚本，不改 App 代码。

### 1.2 非功能需求

| 维度 | 要求 | 架构含义 |
|---|---|---|
| 启动 | 快速、无感 | 无 WebView、无运行时初始化、懒加载 |
| 占用 | 空闲低内存、无后台常驻进程 | 单进程；工具只在运行时拉起，结束即回收 |
| 可扩展 | 加功能不加架构 | 工具包机制 + 自动生成 UI |
| 可维护 | 核心稳定、边界清晰 | 引擎与 UI 分离；工具不依赖 App 内部 |
| 可诊断 | 环境问题可定位 | CLI 探测、版本缓存、结构化日志、诊断包 |
| 安全 | 不任意执行不可信命令 | 参数数组执行、无默认 shell、显式授权 |

### 1.3 由字幕方案反推的硬约束

这份 v1.0 文档实际给出了一个相当苛刻的验收场景，架构必须原生支持：

1. **长任务**：1 小时音频约 30 分钟转写，任务可能跨小时，必须可取消、可观察、可断点。
2. **严格串行**：多个 whisper 并行会互抢 GPU，比串行慢一个数量级 → 需要全局资源调度，而不是每个工具各自为政。
3. **人工检查点**：通读校对产出 `fixes.json` 是不可跳过的质量分水岭 → 流水线要能「暂停等人」，并把人工编辑结果作为下游输入。
4. **中间产物多**：wav / raw.srt / raw.txt / raw.json / fixes.json / final.srt，且有目录约定 → 需要任务工作区和工件（Artifact）模型，而不是临时文件乱飞。
5. **环境脆弱**：jieba 在外置盘、缺了会静默退化；`check_srt.py` 没有 argparse；whisper 首次跑要编译 Metal 着色器 → 需要环境探测（Doctor）与结构化错误，而不是把 stderr 甩给用户。
6. **外部盘**：模型 1.5 GB、临时目录都指向 `/Volumes/APPLE 1TB` → 非沙盒、路径可配置、盘未挂载要能明确报错。
7. **批量逐集交付**：断点续跑 + 单集独立可交付 → 批量应是「任务组」，每个子任务独立状态、独立产物。
8. **机器可读输出**：ffmpeg 的 `-progress pipe:1`、whisper 的 `progress = N%`、ffprobe 的 JSON → 进度解析优先结构化输出，正则只作兜底。

> 结论：这不是「一堆按钮调用命令」那么简单，核心是一个**带检查点与资源约束的任务执行引擎**。GUI 只是它的投影。

## 2. 方案选型

### 2.1 候选矩阵

| 方案 | 冷启动 | 空闲内存 | 包体 | macOS 集成 | 开发速度 | 适合本项目 |
|---|---|---|---|---|---|---|
| **SwiftUI 原生** | 最快（~0.2–0.4 s） | 最低（~60–90 MB） | 最小（~10 MB） | 最好 | 中 | **✅ 推荐** |
| Tauri 2（Rust + WKWebView） | 快（~0.4–0.8 s） | 中（~80–150 MB） | 小（~10–20 MB） | 中（需插件） | 快（Web UI） | 备选 |
| WKWebView + Swift 外壳 | 快 | 中 | 小 | 好 | 中 | 仅当 UI 想用 Web |
| Electron | 慢（1–3 s） | 高（200–400 MB） | 大（100 MB+） | 中 | 最快 | ❌ 与目标冲突 |
| Python + PyQt/Tk | 慢 | 中高 | 中 | 差 | 快 | 仅原型 |
| 纯菜单栏（SwiftBar/xbar） | 最快 | 最低 | 最小 | 中 | 快 | ❌ 不适合长表单/日志/审查 |

> 数值为量级预期，不是实测。冷启动与内存两项已足以淘汰 Electron；Tauri 保留为「团队更熟 Web」时的备选。

### 2.2 为什么选原生 SwiftUI

- **与「低占用、快启动」直接对齐**：没有 Chromium / Node / WebView 初始化，冷启动和内存都是数量级优势。
- **macOS 能力零摩擦**：`NSOpenPanel`、拖拽、Finder 显示、Quick Look、通知、菜单栏、Shortcuts/App Intents、URL Scheme、Services，全部原生。
- **长任务管理天然合适**：`Process` + `AsyncStream` + actor，取消、超时、进程组信号都好做。
- **不需要为跨平台付税**：用户明确只做 macOS，抽象层可以砍掉。
- 语言与工具链已具备：本机 Swift 6.4、macOS 27 SDK；**但目前只装了 Command Line Tools，没有完整 Xcode**（`xcodebuild` 不可用）。早期可用 `swift build` + 手工打 `.app` 包推进；进入签名/公证/图标/资源阶段建议装 Xcode。
- **部署目标建议 macOS 14+**：可用 Observation、成熟的 `NavigationSplitView`；当前开发机 macOS 27 不受影响。

### 2.3 为什么不做纯 Web UI / 纯菜单栏

- 纯 Web UI 会把「低占用快启动」这条首要目标直接牺牲掉，收益只是 UI 开发快；而本项目的 UI 主要是**表单 + 日志 + 审查器**，用 SwiftUI 的声明式表单完全够。
- 纯菜单栏适合「一键动作」，不适合字幕这种多步、带日志、带人工校对的工作流。菜单栏应作为**辅助入口**（当前任务进度、快速运行最近预设），不是主形态。

### 2.4 推荐的 App 形态

- **主窗口**：`NavigationSplitView`，左侧工具库（分类/搜索/最近），右侧工具运行页。
- **任务详情可独立成窗**：长任务可以「在新窗口打开」，主窗口继续干别的。
- **菜单栏状态项（可选）**：显示运行中任务数与总进度，支持暂停队列。
- **系统集成（逐步加）**：Finder 右键 Quick Action、拖文件到 Dock 图标、`mactoolbox://run?...`、App Intents/Shortcuts。
- **不采用文档型 App**（每个任务一个 document）：任务不是文档，生命周期与持久化模型不同。

## 3. 总体架构

### 3.1 分层

```
┌──────────────────────────────────────────────────────────────┐
│  MacToolbox.app  (SwiftUI Shell)                             │
│  工具库 / 动态表单 / 任务控制台 / 审查器 / 设置 / 菜单栏       │
├──────────────────────────────────────────────────────────────┤
│  ToolboxKit  (Swift Package, 无 UI 依赖)                      │
│  ToolRegistry · Manifest · FormSchema · JobEngine             │
│  Pipeline · ProcessRunner · EnvDoctor · ArtifactStore         │
│  ResourceScheduler · EventBus · Persistence · Diagnostics     │
├──────────────────────────────────────────────────────────────┤
│  Tool Protocol  (JSON Lines over stdio，语言无关)             │
├──────────────────────────────────────────────────────────────┤
│  Tool Packages  (.toolbox：manifest + scripts + resources)    │
│  subtitle / video-compress / pdf-merge / ...                  │
├──────────────────────────────────────────────────────────────┤
│  External CLIs：ffmpeg · ffprobe · whisper-cli · python3 ...  │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 四个运行时角色

| 角色 | 职责 | 生命周期 |
|---|---|---|
| **Shell** | 渲染、导航、输入校验、展示 | App 全程 |
| **Core（ToolboxKit）** | 发现工具、校验 manifest、调度、执行、落盘 | App 全程，单进程 |
| **Tool** | 领域逻辑；要么是 manifest 编排，要么是一个可执行脚本 | 按任务拉起，结束回收 |
| **External CLI** | 真正干活 | 由 Tool/Core 拉起 |

### 3.3 依赖规则（硬性）

```
ToolboxProtocol  ←  ToolboxKit  ←  App
                                 ←  ToolboxCLI（可选）
Tool Package     →  只依赖外部 CLI 与 Tool Protocol，不依赖 App 内部
```

- `ToolboxProtocol`：只有数据模型与协议常量，零依赖。
- `ToolboxKit`：不 import SwiftUI/AppKit（允许 Foundation），可单测、可被 CLI 复用。
- `App`：只做 UI 与系统集成，不含领域逻辑。
- 工具作者不需要拿到 App 源码，也不需要编译 Swift。

### 3.4 四条设计原则

1. **声明式优先**：80% 的工具只是「收参数 → 调命令 → 出文件」，用 manifest 描述，UI 自动生成。
2. **领域逻辑下沉到脚本**：切分规则、幻觉过滤、术语表这类复杂逻辑留在 Python 里，App 不重写、不理解。
3. **结构化输出优先**：能用 `-progress pipe:1`、`-of json`、`--output-format json` 就不用正则；正则按工具隔离、可测。
4. **原语少而稳**：执行、审查、文件操作、断言，四种足够；不发明通用工作流 DSL。

## 4. 扩展模型（架构核心）

### 4.1 三级扩展

| 级别 | 形态 | 适用 | 是否改 App | UI |
|---|---|---|---|---|
| **A. 声明式工具包** | `tool.json` + 可选脚本，`run.mode = "steps"` | 单命令、多步固定流水线、批量包装 | 否 | 自动生成 |
| **B. 协议工具** | 任意语言的可执行文件，stdio 上说 JSONL，`run.mode = "protocol"` | 复杂逻辑、需要自定义进度/交互、复用现有 Python 工具 | 否 | 自动生成表单 + 内置审查器 |
| **C. 原生模块** | Swift 协议实现，随 App 编译或签名加载 | 需要深度定制 UI（字幕编辑器、视频预览）或系统集成 | 是 | 自定义 |

> 关键：A 和 B **共用同一套 manifest 与安装机制**。默认从 A 起步；逻辑变复杂时升级到 B，不改 UI 和安装方式；只有必须做特殊界面时才进 C。

### 4.2 Tool Package 目录

```
subtitle.toolbox/
├── tool.json              # 唯一入口，声明一切
├── README.md              # 工具说明（App 内展示）
├── scripts/
│   ├── make_srt.py
│   ├── check_srt.py
│   └── batch_transcribe.py
├── resources/             # 黑名单、默认 fixes 模板等
└── icon.png               # 可选；否则用 SF Symbol
```

- 内置工具放 App `Resources/Tools`，只读。
- 用户工具放 `~/Library/Application Support/MacToolbox/Tools/`。
- 同 id 时用户版本覆盖内置版本，UI 标注「用户版本」。
- 工具可自带小型可执行文件（`bin/`）随包分发；ffmpeg/whisper 这类大型 CLI 仍走外部安装，避免体积与许可问题。
- 工具包本身不写任何运行期数据；所有可写内容进任务工作区。

### 4.3 manifest 设计

字段分五组：身份、依赖、输入、执行、输出。示意（视频压缩）：

```json
{
  "schemaVersion": 1,
  "id": "media.video-compress",
  "name": { "zh-Hans": "视频压缩", "en": "Video Compress" },
  "version": "1.0.0",
  "minAppVersion": "0.1",
  "category": "media",
  "icon": "arrow.down.right.and.arrow.up.left",
  "summary": { "zh-Hans": "按质量或目标体积压缩视频" },

  "requirements": [
    { "kind": "cli", "name": "ffmpeg", "probe": ["-version"],
      "installHint": "brew install ffmpeg" }
  ],

  "inputs": [
    { "key": "video", "type": "file", "label": "视频文件", "required": true,
      "accept": ["mp4", "mov", "mkv"] },
    { "key": "crf", "type": "number", "label": "质量 (CRF)", "default": 23,
      "min": 0, "max": 51 }
  ],

  "run": {
    "mode": "steps",
    "steps": [
      {
        "id": "probe",
        "title": "读取时长",
        "uses": "exec",
        "command": "ffprobe",
        "args": ["-v", "error", "-show_entries", "format=duration",
                 "-of", "json", "-o", "{{job.dir}}/meta.json", "{{inputs.video}}"],
        "artifacts": [{ "id": "meta", "kind": "json", "path": "{{job.dir}}/meta.json" }]
      },
      {
        "id": "encode",
        "title": "转码",
        "uses": "exec",
        "command": "ffmpeg",
        "args": ["-y", "-progress", "pipe:1", "-nostats",
                 "-i", "{{inputs.video}}",
                 "-c:v", "libx264", "-crf", "{{inputs.crf}}",
                 "{{job.dir}}/out.mp4"],
        "progress": { "mode": "regex",
                      "pattern": "out_time=(\\d+):(\\d+):(\\d+)",
                      "durationArtifact": "meta" },
        "artifacts": [{ "id": "out", "kind": "video", "path": "{{job.dir}}/out.mp4" }]
      }
    ]
  },

  "outputs": [{ "artifactId": "out", "revealInFinder": true }]
}
```

字段要点：

| 组 | 字段 | 说明 |
|---|---|---|
| 身份 | `id` / `version` / `category` / `icon` / `summary` | `id` 反向域名；`summary` 可本地化 |
| 依赖 | `requirements[]` | `cli` / `python-module` / `asset`；带探测命令与安装提示 |
| 输入 | `inputs[]` | 类型：`file` `files` `directory` `text` `textarea` `number` `toggle` `select` `secret` |
| 输入 | `validation` / `visibleWhen` | 表单校验与条件显示 |
| 执行 | `run.mode` | `steps` 或 `protocol` |
| 执行 | `steps[].uses` | `exec` / `review` / `copy` / `move` / `assert` |
| 执行 | `args` | **数组**，`{{...}}` 占位符；不经过 shell |
| 执行 | `progress` | `jsonl` / `regex` / `percent` / `none` |
| 执行 | `resources` | `gpu` / `network` / `cpu`，用于全局调度 |
| 批量 | `batch` | 声明可批量：输入字段、扩展名、是否跳过已存在 |
| 执行 | `checkpoint` | 声明审查器与可编辑产物 |
| 输出 | `outputs[]` | 交付物、是否在 Finder 中显示 |
| 设置 | `settings` | 工具级配置（模型路径、输出目录），与输入分离 |
| 资产 | `assets[]` | 大文件下载：URL + SHA-256 + 目标目录 |

**刻意不做的**：manifest 里不写循环、条件分支、变量计算。批量用「任务组」，分支用脚本，模板用 `presets`。这是防止 manifest 长成半门编程语言的关键。

### 4.4 Tool Protocol（B 级工具）

工具是普通可执行文件，stdout 每行一个 JSON 事件，stdin 接收控制消息。语言无关，可脱离 App 用管道直接测。

| 事件（工具 → App） | 载荷 | 用途 |
|---|---|---|
| `hello` | `protocolVersion`, `toolVersion` | 握手与兼容检查 |
| `progress` | `fraction?`, `message?`, `step?` | 驱动进度条 |
| `log` | `level`, `message` | 日志面板 |
| `artifact` | `id`, `kind`, `path`, `label?` | 登记产物 |
| `checkpoint` | `id`, `reviewer`, `artifactId`, `schema?` | 暂停等人 |
| `result` | `ok`, `summary?`, `outputs[]` | 结束 |
| `error` | `code`, `message`, `detail?`, `retryable` | 结构化失败 |

- 控制：App → stdin 发送 `{"type":"cancel"}`、`{"type":"checkpointResult", ...}`；同时发 `SIGTERM`，宽限 3 s 后 `SIGKILL` 进程组。
- 约定：stdout 只放协议事件，**人类可读日志走 stderr 或被包进 `log` 事件**，避免解析污染。
- 价值：现有 Python 脚本可以套一个几十行的 wrapper 就成为工具，且能独立跑 CI。

### 4.5 选择哪一级

```
只是调 1–N 条命令？ ──是──> A（manifest steps）
        │否
需要自定义进度/交互/复用复杂脚本？ ──是──> B（协议）
        │否
必须定制界面或系统集成？ ──是──> C（原生模块）
```

### 4.6 新增一个工具的路径

```
复制 Tools/_template.toolbox
        ↓
改 tool.json（id / 输入 / 步骤）
        ↓
把脚本放进 scripts/
        ↓
拖入「工具管理」或直接放用户工具目录
        ↓
EnvDoctor 检查依赖 → 运行 → 看日志/产物
        ↓
（可选）ToolboxCLI validate / run 做无头验证
```

常见功能的落点，用来校验这套分级是否够用：

| 功能 | 级别 | 理由 |
|---|---|---|
| 视频压缩/转码、抽音、图片格式转换 | A | 单命令 + 参数 |
| PDF 合并/拆分、批量重命名 | A 或 B | 单命令；复杂规则进脚本 |
| 字幕生成 | B | 多步、检查点、GPU 串行 |
| OCR、语音转写、文档转换 | B | 复用 Python 脚本 |
| 带视频预览的字幕编辑器 | C | 定制 UI |

> 判断标准：**如果新增功能需要改 App 代码，先问是不是 UI 问题；只有 UI 问题才配 C 级。**

## 5. 运行时设计

### 5.1 进程执行器（ProcessRunner）

- 参数数组直接 `exec`，**默认不经过 shell**；需要管道时显式 `shell: true` 并在安装时提示风险。
- 独立进程组（`setpgid`），取消时杀整组，避免 ffmpeg 子进程残留。
- 环境隔离：干净环境 + 受控 `PATH`（工具声明目录、`/opt/homebrew/bin`、`/usr/local/bin`、`~/.local/bin`）+ 工具自定义 env。
- 固定注入：`PYTHONUNBUFFERED=1`（否则 Python 日志不实时）、`LANG=en_US.UTF-8`（稳定解析）、`TMPDIR` 指向任务工作区（默认），可由工具设置覆盖。
- 输出：stdout/stderr 分通道读取、逐行解码（UTF-8 容错，处理 `\r` 进度），完整日志落盘，UI 只保留环形缓冲（约 2000 行）。
- 取消：`SIGTERM` → 3 s → `SIGKILL`；清理任务临时文件。
- 超时：步骤级可选；**不设默认总超时**（ASR 可能跑两小时），只对「无输出心跳」告警。
- 不引入 XPC 常驻服务：工具本身就是短命进程，XPC 只增加启动与部署成本；将来确需后台常驻再评估 launchd agent。

### 5.2 任务状态机

```
queued → preparing → running(step i) → waitingReview → running(j) → succeeded
                          │                  │
                          ├→ failed ←────────┘
                          └→ cancelled
```

- 每次状态迁移原子写 `job.json`。
- App 异常退出后，重启时把 `running` 标记为 `interrupted`，提供「继续 / 查看日志 / 丢弃」。
- 断点条件：输入指纹 + 工具版本 + 已完成的步骤与工件哈希一致，才允许从下一步续跑。

### 5.3 Pipeline 与 Artifact

- 步骤是线性的（字幕流程就是线性），不做 DAG 编辑器；需要并行时由工具脚本内部处理。
- 步骤间通过**工件句柄**传递，而不是裸路径：`artifacts.audio.path`，类型驱动 UI（视频可预览、字幕可预览、报告可渲染）。
- 工件登记后不可变；重新生成产生新版本（`v2`），下游引用明确版本。
- 任务工作区：

```
~/Library/Application Support/MacToolbox/Jobs/<job-id>/
├── job.json            # 输入快照、工具版本、步骤状态
├── events.jsonl        # 追加式事件流
├── artifacts/          # 产物与中间物
└── logs/step-*.log     # 原始输出
```

### 5.4 检查点（人工介入）

- 步骤类型 `review`：声明 `reviewer`、输入工件、输出工件、是否可跳过。
- 内置审查器按类型注册，不按工具注册：
  - `fix-table`：原文/修正对照表（字幕 `fixes.json` 场景）
  - `text-diff`：文本差异审阅
  - `report`：只读报告（质检结果）
  - `generic-form`：任意 schema 表单
- 用户提交后，审查结果作为普通工件写入，流水线继续；**审查器不感知具体工具**。
- 引擎只产出 `checkpoint` 事件并等待结果；审查器视图在 App 层按类型注册。
- 这是「LLM 通读校对」的落点：外部 Agent/本地 LLM 生成的候选修正，可以导入为 `fixes.json`，再由用户在 `fix-table` 中确认。

### 5.5 资源调度

- 全局 `ResourceScheduler`（actor），按资源键分配容量：`gpu: 1`、`network: 2`、`cpu: N-1`。
- 工具在 manifest 中声明所需资源；字幕工具声明 `["gpu"]`，因此 whisper 永远串行。
- 这一层直接解决文档里「并行 whisper 慢一个数量级」的坑，且是所有工具共享的约束，不靠用户自觉。
- 资源按 key 排序获取，避免死锁；等待中的任务按 FIFO 恢复。
- **demo 实现**：批量调用统一经过 `JobCoordinator`，它先 `acquire` 再 `start`，子任务结束释放；
  当前只有一个前台 coordinator，所以 GPU 串行是确定性的。

### 5.6 批量任务

- 批量 = **任务组（JobGroup）**：父任务只负责枚举与串行调度，每个子任务独立工作区、独立状态、独立交付。
- 这正好匹配「逐集交付、断点续跑」：一集失败不影响已完成集。
- 枚举规则：目录 + `batch.accept` 扩展名过滤；组级进度 = 子任务进度均值。
- 跳过已存在：按输出目录/视频目录 + 目标扩展名判断，命中则子任务记 `skipped`，不占 GPU。
- **demo 实现**：`JobCoordinator.startBatch` 创建 group + N 个 child，child 各自一条 record；
  `stopOnError` 可配置为某项失败即停，默认继续并汇总失败数。

### 5.7 持久化

| 数据 | 位置 | 形式 |
|---|---|---|
| 任务组 / 子任务 | `Application Support/MacToolboxDemo/records.json` | JSON（demo 版索引） |
| 偏好 | 同上 `preferences.json` | JSON（收藏/置顶/最近/集合/工具参数） |
| 任务详情 | `Jobs/<id>/config.json` + `job.log` + 产物 | 文件 |
| 密钥 | 任务 `config.json` | demo 明文；生产应 Keychain |

- 启动时 `JobStore` 读取 `records.json`，把 `running` / `waiting` 标成 `interrupted`。
- 任务页显示历史组、子任务状态、计数；`interrupted` / `failed` 组可「继续」。
- `resume` 把 config 里 `"resume": true` 传给 Python，按产物存在情况跳过已完成步骤。
- **偏差**：设计稿写 SQLite，demo 用单个 JSON 文件；300 条以内足够，后续再换 SQLite。

### 5.7.1 偏好与集合

- `PreferencesStore` 管理收藏、置顶、最近使用、所选集合、工具参数。
- 工具参数按字段类型过滤：`secret` 不写盘，避免 API Key 进入 preferences。
- `ToolCollection` 由「全部工具」+ 按 `category` 自动生成的集合组成；
  侧栏顶部下拉切换，主页按集合过滤。
- 后续可扩展为用户自定义集合（拖拽排序、CRUD）；当前先保证层级和持久化。

### 5.8 环境探测与资产

- `EnvDoctor`：按 manifest 的 `requirements` 探测命令是否存在、版本是否满足，结果缓存（可手动刷新）。
- UI 在工具页顶部显示三色状态；缺失时给出安装命令（复制按钮），不静默失败。
- 支持 `python-module` 探测（如 jieba），并可指定 `PYTHONPATH` 候选路径 —— 直接对应文档里 jieba 的两个坑。
- `AssetStore`：模型等大文件的下载、断点续传、SHA-256 校验、可配置根目录（默认允许放外置盘）。whisper 模型、VAD 模型都走这里。
- 盘未挂载：探测失败给出明确原因与「重新检测」，而不是让脚本静默退化。

### 5.9 日志与诊断

- `os.Logger` 分 subsystem/category；任务日志独立文件。
- 「导出诊断包」：App 版本、工具清单与哈希、环境探测结果、最近 N 行日志、系统信息。CLI 外壳类工具的头号故障是环境，诊断包能显著降低维护成本。
- 敏感信息在落盘前脱敏（密钥、token）。

## 6. UI 架构

### 6.1 信息架构

参考 Apple 捷径的「卡片库」形态，而不是「一个工具一页大表单」。

```
侧边栏
├─ 集合选择器  → 全部工具 / 按类型自动生成的集合
├─ 主页        → 卡片式工具库（最近 / 收藏 / 分类 + 搜索）
├─ 任务        → 当前组、子任务、历史、断点续跑
├─ 工具管理    → 已安装工具、收藏/置顶、工具目录、环境
└─ 设置        → 环境、运行数据、工具参数、集合、关于
```

- 主页卡片：图标、名称、一句话说明、分类标签、置顶/收藏角标；点卡片进详情，
  工具栏「快速运行」、卡片右键或 `⌘R` 进浅层快速运行，`⌘B` 进批量。
- 工具详情：**环境一行 → 常用参数 → 运行**；其余参数收进「全部参数…」。
- 任务页：组进度、子任务状态、历史、失败/中断继续；控制台查看单前项日志。
- 菜单栏提供深层入口：`⌘1`–`⌘4` 切换页面，`⌘R` 快速运行，`⌘B` 批量，`⌘,` 高级设置。

### 6.2 浅层与深层

这是本设计刻意分开的两层，避免默认界面被几十个参数淹没：

| 层 | 入口 | 内容 | 面向 |
|---|---|---|---|
| **浅层** | 工具栏「快速运行」/ `⌘R` / 工具详情 | `quick.inputs` 声明的 2–4 个字段（视频、预设、校对方式） | 日常快速使用 |
| **深层** | 「全部参数…」/ `⌘,` / 卡片菜单 | manifest 全量字段 + 环境检测 + 恢复默认 | 高级用户 / 排障 |

- 两层共用同一份工具参数，浅层不产生第二套配置。
- `quick` 在 manifest 中显式声明，未声明时回退到「必填字段 + 非高级字段」。
- 深层设置是 sheet，不打断主页；修改立即生效。
- 高级选项在深层按 `group` 分卡片，不在默认页面出现。

### 6.3 审查器

- 按 `reviewer` 类型注册的独立视图，接收工件与 schema，输出 JSON 工件。
- 字幕场景的 `fix-table`：左侧原文、右侧修正、计数、按「长串优先」排序提示；支持导入/导出 `fixes.json`。
- 审查器是声明式 UI 体系中唯一需要按需定制的交互面；通过「工件类型 + 审查器类型」复用，而不是给每个工具写页面。

### 6.4 系统集成

| 能力 | 时机 |
|---|---|
| 完成通知（UNUserNotificationCenter） | P1 |
| 在 Finder 中显示 / Quick Look | P1 |
| 菜单栏进度 | P2 |
| 拖文件到 App 图标 / Dock | P2 |
| App Intents / Shortcuts | P3 |
| `mactoolbox://` URL Scheme | P3 |
| Finder Quick Action / Services | P3 |
| 可选 CLI（`toolbox run ...`） | P3，同时强制引擎与 UI 解耦 |

## 7. 用字幕工具验证架构

### 7.1 流程映射（原方案 6 步，抽音/转写拆成两步看）

| 文档步骤 | 架构落点 | 关键设计 |
|---|---|---|
| 1 预检 ffprobe | `exec` + 结构化输出 | 解析 JSON；无音轨 → `assert` 失败，不进入下一步 |
| 2 抽音 ffmpeg | `exec` | `-progress pipe:1` 结构化进度 |
| 3 转写 whisper-cli | `exec` + `resources:["gpu"]` | 正则 `progress = (\d+)%`；任务串行；首次编译提示 |
| 4 通读校对 | `review` | `fix-table` 审查器；可跳过；产出 `fixes.json` |
| 5 字幕工程 make_srt.py | `exec` | 复用现有脚本；退出码即失败 |
| 6 质检 check_srt.py | `exec` + 结构化报告 | 硬失败 exit 1 → 步骤失败；软指标渲染成报告 |
| 7 交付 | `copy` + `outputs` | 同名同目录；在 Finder 中显示；逐集交付 |

### 7.2 环境坑的架构化处理

| 文档中的坑 | 架构对策 |
|---|---|
| jieba 缺失静默退化 | `requirements` 声明 `python-module: jieba` + 候选路径；缺失时工具页红色告警，不启动 |
| `check_srt.py` 无 `--help` | 工具 manifest 固化调用方式，UI 不暴露任意参数 |
| 并行 whisper 更慢 | 全局 `gpu:1` 资源锁 |
| 中间产物吃主盘 | `TMPDIR` 指向任务工作区，工作区根目录可配置到外置盘 |
| 外置盘未挂载 | 资产/路径探测失败 → 结构化错误 + 重试；不静默退化 |
| 长音频复读 | 工具脚本内部处理分块；App 只负责串行与断点 |
| 批量中途失败 | 任务组：子任务独立，完成后立即交付 |

### 7.3 为什么这个场景能验证架构

它同时覆盖了：外部 CLI 调用、多步流水线、结构化进度、人工检查点、资源串行、大文件资产、批量与断点、质检门禁、文件交付。能跑通它，其他「单命令包装」类工具都是降维。

## 8. 工程结构

### 8.1 仓库布局

```
MacToolbox/
├── App/                        # Xcode app target（SwiftUI Shell）
│   ├── Shell/                  # 导航、窗口、菜单、菜单栏
│   ├── Views/                  # 工具库、表单、任务控制台
│   ├── Reviewers/              # 内置审查器
│   └── Resources/              # 图标、本地化、内置工具
├── Sources/
│   ├── ToolboxProtocol/        # 协议与数据模型（零依赖）
│   ├── ToolboxKit/             # 引擎（无 UI）
│   └── ToolboxCLI/             # 可选：manifest 校验/运行工具
├── Tools/                      # 内置工具包
│   ├── subtitle.toolbox/
│   ├── video-compress.toolbox/
│   └── _template.toolbox/
├── Tests/
│   ├── ToolboxKitTests/
│   └── Fixtures/               # 假 CLI、样例输出
├── docs/
└── Scripts/                    # 打包、签名、公证
```

- 根目录 `Package.swift` 管三个 Swift 模块；App 由 Xcode 工程引用本地包。
- 只有 CLT 时：`swift build` / `swift test` 可用；`.app` 用脚本组装（Info.plist + 资源 + `codesign`）。进入图标、公证、App Intents 阶段再装 Xcode。

### 8.2 模块职责

| 模块 | 职责 | 禁止 |
|---|---|---|
| `ToolboxProtocol` | manifest、事件、任务/工件模型、版本常量 | 依赖任何东西 |
| `ToolboxKit` | 发现、校验、调度、执行、持久化、诊断 | 依赖 SwiftUI/AppKit |
| `App` | 渲染与系统集成 | 写领域逻辑、直接拼命令行 |
| `ToolboxCLI` | 校验 manifest、无头运行、CI | 复制引擎逻辑 |

### 8.3 构建与分发

- 开发期：`swift build` + 本地 `.app`；核心逻辑用 `swift test`。
- 发布：Developer ID Application 证书 → hardened runtime → `notarytool` 公证 → staple。
- **明确不启用 App Sandbox**：沙盒会限制执行任意路径的外部 CLI、访问外置盘与 `~/.hermes` 脚本，与本项目定位冲突。
- 代价：不能上 Mac App Store；首次打开可能触发 Gatekeeper 提示，需公证解决。
- 自用可先 ad-hoc 签名；要分发给别人再做公证。

### 8.4 测试策略

1. **单元**：manifest 解码/校验、参数模板、进度解析、状态机迁移、调度器并发。
2. **契约**：用假工具可执行文件跑 Tool Protocol，校验事件序列与取消行为。
3. **流水线**：fixture 驱动的端到端（假 ffmpeg/whisper 输出），验证检查点、断点、失败恢复。
4. **UI**：先手动；稳定后加关键路径 UI 测试。
5. **真实冒烟**：字幕工具用 30 秒短片跑全流程，作为发布前门禁。

## 9. 性能与低占用

### 9.1 目标

| 指标 | 目标 |
|---|---|
| 冷启动 | P50 < 400 ms（Apple Silicon，SSD） |
| 空闲内存 | 60–90 MB |
| App 本体 | < 20 MB（不含工具资产/模型） |
| 空闲 CPU | 0，无后台轮询 |
| 执行开销 | 相对直接跑 CLI，额外 < 50 ms |
| 日志内存 | 有界（环形缓冲），完整日志在磁盘 |

### 9.2 手段

- 无 WebView、无 Node/Rust 运行时、无 Python 嵌入。
- 工具索引与 manifest 懒加载；启动只读设置 + 最近任务。
- 不预探测所有 CLI；探测结果缓存，按需刷新。
- 任务日志流式写盘，UI 只保留尾部。
- 工具进程结束即回收；空闲不保留任何工具进程。
- 不做全盘扫描；目录枚举只在用户选择后发生。
- 避免大图资源与启动时网络请求。

### 9.3 反模式（明确禁止）

- 用 shell 字符串拼命令（空格/中文/注入问题）。
- 每个功能写一个 SwiftUI 页面（不可维护）。
- 把 ffmpeg/whisper 的人类可读输出当稳定 API（解析脆弱）。
- 在 App 内嵌完整 Python 运行时（体积与维护成本）。
- 所有任务共享一个全局临时目录（冲突、难清理）。
- 并行跑 whisper。
- 用 UserDefaults 存任务历史。
- 启动时扫描全盘或探测所有 CLI。

## 10. 安全、权限与分发

### 10.1 执行安全

- 命令与参数分离，默认无 shell。
- 运行前展示「将要执行」的完整 argv（可折叠），首次运行新工具时提示。
- 工件路径限制在任务工作区内；工具包不能写 App Bundle。
- 下载资产校验 SHA-256；工具包可选签名（后续）。
- 密钥进 Keychain；日志脱敏。

### 10.2 TCC / 隐私

- 文件通过 `NSOpenPanel` 选择，TCC 会授予该路径访问。
- 访问 `~/Movies`、外置盘等目录时按需授权；不主动申请 Full Disk Access。
- 全本地运行，无遥测；崩溃日志默认只留在本机。
- 若未来接云端 LLM/STT，单独声明网络权限与数据流向。

### 10.3 分发

- 非沙盒 + Developer ID + 公证。
- 依赖 Homebrew 安装的 CLI，App 只探测不擅自安装；安装命令可复制。
- 不在首版打包 ffmpeg（许可与体积），后续如需可做「受管运行时」目录。
- App 更新可用 Sparkle 2 + appcast（P5）；工具包独立版本，先手动更新，后续再做签名更新通道。

## 12. 风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| SwiftUI 动态表单复杂度失控 | 维护成本上升 | 限定字段类型与原语；复杂 UI 才进 C 级 |
| 解析 CLI 输出脆弱 | 进度/状态错 | 结构化输出优先；解析器按工具隔离并可测 |
| manifest 演化成 DSL | 难维护、难调试 | 禁止循环/分支/计算；逻辑进脚本 |
| 长任务跨 App 退出 | 任务丢失 | 状态落盘 + 退出确认 + 中断恢复 |
| 非沙盒分发摩擦 | 安装体验 | 公证；文档说明；自用 ad-hoc |
| 工具协议版本漂移 | 兼容问题 | `schemaVersion` + 握手 + `minAppVersion` |
| 外置盘/环境差异 | 静默失败 | EnvDoctor + 诊断包 + 明确错误 |
| 过度抽象 | 首版难产 | 只做线性步骤；批量用任务组；先跑穿字幕 |

### 第九批落地：图片格式转换

- **普通工具**：新增 `media.image-convert`，不引入 `nativeView`；继续走 manifest + JobRunner +
  Tool Protocol，复用单任务控制台、批量池、队列、产物和通知。
- **混合编码器**：ffmpeg 负责 JPEG/PNG/TIFF/BMP/GIF/ICO/APNG/QOI/JP2/EXR/TGA；cwebp 负责
  WebP（GIF 动画在无缩放时走 gif2webp）；avifenc/sips 负责 AVIF；sips 负责 HEIC 和
  HEIC/AVIF/SVG/PDF/ICNS/RAW 输入；cjxl/djxl 负责 JPEG XL。
- **alpha 边界**：ffmpeg 可保留 PNG/TIFF/WebP/GIF/APNG/ICO 的 alpha；HEIC/AVIF 的 alpha 由
  sips 解码后进入统一 PNG；JPEG/BMP 没有 alpha，使用 ffmpeg `geq` 按白底/黑底合成；
  目标 AVIF/HEIC/JXL 使用 avifenc/sips/cjxl 保留 alpha。
- **EXIF/ICC**：exiftool 在编码后的临时文件上复制 EXIF/GPS/XMP/IPTC/ICC；先按 ffmpeg 的
  自动旋转结果设置 `Orientation#=1`，并更新 `ExifImageWidth#/ExifImageHeight#`，删除旧缩略图；
  GIF/BMP/ICO/APNG 没有 EXIF 写入能力，跳过并提示；exiftool 缺失时只转换像素。
- **安全交付**：临时文件写在目标目录，成功后 `os.replace`；同名文件默认 `-1`/`-2`，
  也支持覆盖或失败；覆盖源文件时先完成元数据复制再替换。
- **动图**：GIF → WebP 无缩放时保留动画；GIF/WebP/APNG → GIF/APNG 保留动画；
  其余静态输出只取第一帧并在日志提示。

### 第十批落地：视频格式转换

- **普通工具**：新增 `media.video-convert`，继续走 manifest + JobRunner + Tool Protocol，
  复用文件拖拽框、批量池、队列、控制台、通知和产物。
- **封装/编码**：ffmpeg 负责 MP4/MOV/MKV/WebM/AVI/GIF；libx264、libx265、libsvtav1、
  libvpx-vp9、prores_ks；音频 AAC/Opus/MP3/FLAC/ALAC/PCM/复制/无。
- **预设**：通用 MP4、Apple HEVC、WebM VP9、AV1 MKV、ProRes 422 MOV、GIF、仅换封装。
- **兼容性校验**：编码前检查封装/编码组合；WebM 仅 VP9/AV1 + Opus，MP4 不允许
  ProRes/PCM；复制流时禁止改分辨率/帧率；复制音频时检查源编码能否进目标封装。
- **流处理**：重编码只映射首条视频/音频并丢弃字幕；视频+音频都复制时使用
  `-map 0 -c copy` 保留全部流。复制全部流到 MP4/MOV/WebM 且源带字幕时提前报错，
  建议改用 MKV 或关闭复制全部流。
- **画面**：质量 1–100 映射 CRF；分辨率按显示方向限制高度并取偶数；帧率只降不升；
  MP4/MOV 加 `+faststart`；GIF 使用 fps + scale + palettegen/paletteuse。
- **安全交付**：临时文件写在目标目录，成功后 `os.replace`；同名默认 `-1`。

### 第十一批落地：图片 OCR 原生工具

- **nativeView**：新增 `media.image-ocr`，`nativeView=imageOCR`，GUI 由 SwiftUI 直接渲染，
  不经过 JobRunner/Protocol；`ToolValidation`/`tool_lint` 的 nativeView 白名单扩展到
  `homebrew` / `imageOCR`。（第十二批补了 CLI 路径，GUI 与 CLI 共用 manifest。）
- **系统 OCR**：`ImageOCRView` 使用 VisionKit `ImageAnalyzer` + `.text`，
  直接走 macOS Live Text；不引入 Python、tesseract 或网络请求。
- **输入**：文件选择、拖拽 fileURL/image、剪贴板图片/文件 URL；支持 PNG/JPEG/HEIC/
  TIFF/GIF/WebP/BMP；文件读取时用 ImageIO 的 EXIF orientation 传给 ImageAnalyzer。
- **结果**：`ImageAnalysis.transcript` 放入可编辑 TextEditor；支持一键复制、保存 TXT、
  清空、重新识别、语言选择、字符/行数/耗时统计。
- **异步与取消**：识别通过 Task 执行，新图片/新语言会取消旧任务；token 防止旧结果回写。
- **隐私**：OCR 在本机完成；不写 job records/config，不保存图片路径历史。

### 第十三批落地：AgentJobs、跨进程调度与完整 MCP

- **共享状态层**：新增 `scripts/agent_jobs.py`，把每个 CLI/MCP/批量任务的状态写到
  `AgentJobs/<jobID>/job.json`（原子写），事件写 `events.jsonl`，取消写 `cancel.request`；

  gpu=1 / network=2 / cpu=N-1，GUI 与 CLI 真正互斥；等待中显示 `queued`。

- **MCP 完整能力**：`mct mcp` 改为异步 `tools/call`（线程池），支持

- **Agent 任务可视化**：MCP/CLI 调用同样写 AgentJobs，任务页与菜单栏能实时看到
