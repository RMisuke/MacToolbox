# 新工具开发指南（Agent 版）

面向要在这个仓库里新增 `MacToolbox` 工具的 Agent。目标：**只写工具包，不改 App 代码**，
并且让工具同时具备 **GUI 表单**、**CLI** 和 **Agent 工具目录** 三种入口。

本指南按当前代码实现编写，不是未来设计稿；与实现冲突时，以
`Sources/ToolboxCore/Manifest.swift`、`Sources/ToolboxCore/ToolValidation.swift`
和 `scripts/toolbox_spec.py` 为准。契约版本：**Manifest 1 + Agent 标准 0.2**。

> **硬性标准（2026-10 起）**
> 1. 每个工具都必须有 `run`（包括 `nativeView` 工具）；
> 2. 每个工具都必须声明 `agent` 块；
> 3. `run` 必须能被 `mct run <id>` 调用，并输出 Tool Protocol JSONL；
> 4. `mct validate --strict` 必须 0 error；
> 5. 工具不能把领域逻辑写进 Swift；GUI 只是 manifest 的渲染器。

---

## 1. 先判断：要不要写新工具

适合做成工具包：

- 收参数 → 调 CLI / Python → 产出文件；
- 需要独立进度、日志、产物、检查点；
- 希望复用现有脚本，不想改 SwiftUI。

不适合：

- 需要深度定制界面（视频预览、字幕时间轴编辑器）；
- 需要 App 内部状态、系统级窗口集成；
- 只是给现有工具加一个参数（改 `tool.json` 即可）。

新增工具的标准路径：

```text
python3 scripts/new_tool.py --id demo.echo --name "回显" --category "示例"
→ 得到 ~/Library/Application Support/MacToolboxDemo/Tools/demo.echo.toolbox
→ 改 tool.json + scripts/tool.py
→ python3 scripts/tool_lint.py <工具目录>
→ App「工具管理 → 重新扫描」
→ 运行、看日志/产物
```

内置工具在仓库 `Tools/<id>.toolbox/`；用户工具在
`~/Library/Application Support/MacToolboxDemo/Tools/`。同 id 时用户工具覆盖内置工具。
以 `_` 开头的目录（如 `_template.toolbox`）不会被扫描进工具列表。

## 2. 最小工具包

```text
demo.echo.toolbox/
├── tool.json          # 唯一入口：身份 / agent / inputs / run
├── README.md          # 给人看；不参与运行
└── scripts/
    └── tool.py        # Tool Protocol 实现（run/doctor/setup）
```

`tool.json` 最小可用版本：

```json
{
  "schemaVersion": 1,
  "id": "demo.echo",
  "name": "回显工具",
  "version": "0.1.0",
  "category": "示例",
  "icon": "wrench.and.screwdriver",
  "summary": "把输入文本重复输出",
  "inputs": [
    {
      "key": "text",
      "type": "textarea",
      "label": "输入文本",
      "default": "hello",
      "required": true,
      "group": "基础",
      "help": "要输出的文本。"
    }
  ],
  "quick": { "inputs": ["text"] },
  "agent": {
    "capability": "demo.echo",
    "description": "把输入文本重复输出，用于验证 CLI/Agent 链路。",
    "stability": "experimental",
    "readOnly": false,
    "idempotent": true,
    "timeoutSec": 120,
    "checkpoint": "never",
    "tags": ["text", "demo"],
    "outputs": ["text"],
    "examples": [
      { "title": "重复两次", "inputs": { "text": "hello" } }
    ]
  },
  "run": {
    "command": "/usr/bin/env",
    "args": ["python3", "{{toolDir}}/scripts/tool.py", "run", "--config", "{{configFile}}"]
  },
  "doctor": {
    "command": "/usr/bin/env",
    "args": ["python3", "{{toolDir}}/scripts/tool.py", "doctor", "--config", "{{configFile}}"]
  },
  "setup": {
    "command": "/usr/bin/env",
    "args": ["python3", "{{toolDir}}/scripts/tool.py", "setup", "--config", "{{configFile}}"]
  }
}
```

`run` / `doctor` / `setup` 都是**同一种** `{command, args}` 对象，模板变量也一致；
没有外部依赖可以不写 `setup`，但写了就必须能独立运行并返回 `result`。

> 当前执行器只支持 `run.command + run.args`。`run.mode = "steps"` **尚未实现**，
> 不要写 `steps[]`、`uses`、`outputs[]` 这些设计稿字段。
>
> `nativeView` 是 C 级内置工具的入口（如 Homebrew 管理器、图片 OCR）。它只决定 **GUI**
> 怎么渲染，不替代 CLI：声明了 `nativeView` 的工具仍然必须声明 `run` + `agent`，
> 否则只能 GUI 使用，Agent 无法调用。普通新工具不要设置 `nativeView`。
>
> 确实需要定制 SwiftUI 界面时，按
> [`原生工具开发指南.md`](原生工具开发指南.md) 的三处注册点与测试清单执行；
> 新增原生工具一定会改 Swift 源码，这是 C 级工具与 A/B 级工具的核心区别。

## 3. manifest 字段（当前实现）

### 3.1 顶层

| 字段 | 必填 | 说明 |
|---|---|---|
| `schemaVersion` | 是 | 固定 `1` |
| `id` | 是 | 小写反向域名，`^[a-z0-9][a-z0-9._-]*$`，全局唯一 |
| `name` | 是 | 显示名，普通字符串（不是多语言对象） |
| `version` | 是 | 建议 `0.1.0`；参与缓存指纹 |
| `category` | 否 | 中文分类，如 `媒体`、`文档`、`开发`、`系统`、`示例` |
| `icon` | 否 | SF Symbol 名称，如 `captions.bubble` |
| `summary` | 否 | 卡片一句话说明 |
| `agent` | **是（新标准）** | Agent/CLI 元数据；见 §3.4。旧工具缺失仍可运行，但 `--strict` 报错 |
| `requirements` | 否 | 依赖声明；当前**只展示，不自动探测**，真正探测在 `doctor` 脚本 |
| `inputs` | 是 | 表单字段；普通工具至少一个，零输入工具可为空（必须声明 `run`） |
| `presets` | 否 | 参数预设，`values` 只能覆盖已存在的 input key |
| `quick` | 否 | 快速运行字段；`inputs` 必须引用 input key |
| `promptPresets` | 否 | LLM Prompt 预设；`custom` 允许空 prompt |
| `resources` | 否 | `gpu` / `network` / `cpu`，参与全局调度 |
| `batch` | 否 | 批量声明；见 §5 |
| `run` | **是** | `{ "command": "...", "args": [...] }`；GUI 与 CLI/Agent 共用 |
| `nativeView` | 否 | 仅内置原生工具使用；当前支持 `homebrew` / `imageOCR`；仍需 `run` |
| `doctor` | 否 | 环境检测命令；见 §6 |
| `setup` | 否 | 环境修复命令；见 §6 |

`requirements` 的形状：

```json
"requirements": [
  {
    "kind": "cli",
    "name": "ffmpeg",
    "installHint": "brew install ffmpeg",
    "optional": false
  }
]
```

`kind` 允许 `cli` / `python-module` / `asset`；`optional` 只影响展示。
`icon` 不校验 SF Symbol 白名单；建议使用系统常见名称，找不到时界面会显示占位。
App 不会自动执行安装；需要真正检测时在 `doctor` 里发 `env` 事件。

零输入工具（例如 `status`）可以声明 `"inputs": []`，但必须有 `run`；
GUI 会显示空表单，CLI 仍可运行。单文件工具不声明 `batch` 是正常的，
只有确实支持目录批量的工具才声明。

### 3.2 inputs

```json
{
  "key": "video",
  "type": "file",
  "label": "视频文件",
  "required": true,
  "default": "",
  "accept": ["mp4", "mov"],
  "placeholder": "选择文件",
  "help": "只读，不会修改原文件。",
  "group": "基础",
  "advanced": false,
  "visibleWhen": { "field": "backend", "equals": "local" }
}
```

支持的类型：

| type | UI | 值 | 备注 |
|---|---|---|---|
| `file` | 拖拽框 + 中间「选择文件…」 | 路径字符串 | `accept` 不带点；框内可直接拖入文件 |
| `directory` | 目录选择 | 路径字符串 | |
| `text` | 单行输入 | 字符串 | |
| `textarea` | 多行 | 字符串 | |
| `number` | 数字输入 | 数字 | `min` / `max` |
| `toggle` | 开关 | 布尔 | |
| `select` | 下拉 | 字符串 | `options` 必须非空，`default` 必须在 options 内 |
| `secret` | 安全输入 + Keychain | 字符串 | 见 §7 |
| `model` | 输入 + 获取模型列表 | 字符串 | 必须声明 `modelSource.baseURLField` |
| `preset` | 预设选择器 | 字符串 | 通常 key 叫 `preset`；App 有内置“自定义”逻辑 |
| `lexicon` | 词表 Profile 选择 | 字符串 | 需要工具自己消费 `_lexicon*` 字段 |

字段约束：

- `key` 只能字母/数字/下划线，不能以数字开头；`MCT_SECRET_<key>` 会作为环境变量名。
- `required: true` 的字段为空时，App 会拦截运行。
- `help` 建议必填；`tool_lint` 会对缺失 help 发 warning。
- `visibleWhen.equals` 是标量（字符串/数字/布尔）。
- `advanced: true` 的字段只在「全部参数」里显示。
- `file` 不写 `accept` 表示接受任意文件；写了就按扩展名过滤（不带点）。
- `directory` 支持 `placeholder`；它只是 UI 提示，CLI/Agent 不会使用。
- `quick` 可以只有 `inputs`；`title` / `defaults` 可选。`title` 缺省时 App 用
  「快速开始」，不影响 CLI。

**preset 与默认值**

- `default` 必须是该字段类型的正确标量：`number` 用数字，`toggle` 用布尔，
  `select` 默认值必须存在于 `options`；
- `presets[].values` 只能覆盖已有 input key；显式 `--input` 会覆盖 preset；
- `preset` 字段的 `options` 可以包含 `custom`；`presets` 与 `options` 不要求一一对应。

`modelSource` 示例：

```json
{
  "key": "llmModel",
  "type": "model",
  "label": "LLM 模型",
  "modelSource": { "baseURLField": "llmBaseURL", "apiKeyField": "llmAPIKey" }
}
```

`preset` 字段由 App 自动应用 `presets[].values`；自定义预设存在
`presets.json`，不会写回工具包。

### 3.3 模板变量

`run` / `doctor` / `setup` 的 `command` 和 `args` 支持：

| 变量 | 值 |
|---|---|
| `{{toolDir}}` | 工具包绝对路径 |
| `{{jobDir}}` | 当前任务目录 |
| `{{configFile}}` | 当前 `config.json` 绝对路径 |
| `{{toolID}}` | 工具 id |

命令以参数数组执行，不经过 shell。不要把多个参数拼成一个字符串。
需要 shell 特性时，自己在脚本里做，不要写 `sh -c`。


### 3.4 Agent 标准（新工具必须）

`agent` 块是工具进入 Agent 工具目录的「身份证」。它不改变执行逻辑，但决定
`mct list/describe/schema` 和 MCP 客户端看到什么。

```json
"agent": {
  "capability": "media.image.convert",
  "description": "把单张图片转换为 JPEG/PNG/WebP 等格式；批量用 mct batch。",
  "stability": "stable",
  "readOnly": false,
  "idempotent": true,
  "timeoutSec": 900,
  "checkpoint": "never",
  "tags": ["image", "convert", "batch"],
  "outputs": ["image"],
  "examples": [
    { "title": "PNG 转 WebP", "inputs": { "image": "/tmp/a.png", "format": "webp" } }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `capability` | 建议 | 稳定能力 id，小写反向域名；默认 = 工具 id |
| `description` | 建议 | 给 Agent 看的能力说明；默认 = `summary` |
| `stability` | 否 | `experimental` / `stable` / `deprecated`；默认 `experimental` |
| `readOnly` | 否 | 是否不修改任何文件/系统；写产物也算修改，通常应为 `false`。MCP `readOnlyHint` 会使用 |
| `idempotent` | 否 | 相同输入重复执行是否安全；影响 Agent 重试策略 |
| `timeoutSec` | 否 | 默认超时；`mct` 用它兜底，正数。默认 3600，短任务建议 60–300，长转码/转写 1800–7200 |
| `checkpoint` | 否 | `never` / `manual` / `auto`；默认 `never`。人工校对类工具用 `manual` |
| `tags` | 否 | 检索标签 |
| `outputs` | 否 | artifact kind 列表，必须与工具实际发出的 artifact kind 对齐；见 §4.3 |
| `examples` | 否 | 示例输入；key 必须存在于 `inputs`；`mct describe` 会生成 CLI 命令 |

- `readOnly` 表示「不产生任何副作用」，不是「只读输入」。例如 OCR 只读图片但会写
  `ocr.txt`，应声明 `readOnly: false`；
- `outputs` 不是描述性文字，而是 Agent 用来判断产物类型的契约；建议只使用
  §4.3 的标准 kind，或至少与 `artifact.kind` 完全一致；
- `examples` 至少给 1 个；`inputs` 的 key 必须存在，值要能通过类型校验。

`checkpoint` 的语义：

- `never`：`mct` 不会主动停；若工具仍发 `checkpoint`，按 `auto` 继续；
- `auto`：收到 `checkpoint` 立即发送 `{"type":"continue",...}`；
- `manual`：TTY 下询问用户；非 TTY（Agent/脚本）下**退出码 6** 并保留 jobDir，
  人工改完产物后执行 `mct resume --job <dir> --checkpoint auto`。

### 3.5 统一 CLI 契约

所有工具都通过 `bin/mct` 暴露，不需要工具作者再写一套参数解析：

```bash
bin/mct list --json
bin/mct describe <tool-id> --json      # 完整 Agent 描述 + inputSchema
bin/mct schema <tool-id>               # 只输出 inputs 的 JSON Schema
bin/mct schema --all --format openai   # OpenAI function tools
bin/mct schema --all --format mcp      # MCP tools/list
bin/mct validate --all --strict
bin/mct doctor <tool-id> --json
bin/mct setup <tool-id> --json
bin/mct run <tool-id> --input key=value
bin/mct batch <tool-id> --input <batchInput>=<dir>
bin/mct resume --job <jobDir>
bin/mct jobs list --json               # 与 GUI 同一份 Agent 任务状态
bin/mct jobs show <jobID> --json
bin/mct jobs cancel <jobID>
bin/mct install <dir|zip>               # 安装到用户 Tools/
bin/mct uninstall <tool-id> --yes       # 只删用户 Tools/
bin/mct mcp                            # MCP stdio server
```

`mct run` 的行为（新工具必须兼容）：

1. 读 manifest，补默认值，应用 `presets`；
2. 校验 required / select / number / file / directory；
3. 生成 `Jobs/<时间>-<id>-<短id>/config.json`（含 `_meta`、`resume`、指纹）；
4. 以 jobDir 为 cwd 启动 `run`；
5. 解析 stdout JSONL；stderr 作为人类日志；
6. 写 `mct-result.json`，stdout 输出最终 JSON。

最终 JSON 的关键字段：

```json
{
  "ok": true,
  "status": "succeeded",
  "tool": "media.image-convert",
  "jobID": "...",
  "jobDir": "/abs/Jobs/...",
  "exitCode": 0,
  "summary": "...",
  "artifacts": [{"id":"image","kind":"image","path":"/abs/out.webp"}],
  "error": null,
  "durationMs": 728
}
```

退出码：

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 工具失败（含 `result.ok=false` / 非 0 退出） |
| 2 | 参数或契约错误 |
| 3 | 工具不存在 |
| 4 | 超时 |
| 5 | 取消 |
| 6 | 等待人工检查点（jobDir 已保留） |

### 3.6 低层 CLI 仍然保留

调试或 CI 可以绕过 `mct` 直接跑协议：

```bash
python3 <tool>/scripts/tool.py run --config /abs/job/config.json
python3 <tool>/scripts/tool.py doctor --config /abs/job/config.json
python3 <tool>/scripts/tool.py setup --config /abs/job/config.json
```

但 Agent 不应自己拼 `config.json`：`_meta`、secret、指纹、jobDir 都由 `mct` 负责。
工具脚本只需要保证这三个子命令可用，并严格遵守 §4 的协议。

### 3.7 机器可读接口

- `mct describe <id> --json`：完整描述（inputs、presets、batch、resources、examples、CLI）。
- `mct schema <id>`：`type/object + properties + required`，字段类型映射：
  `file/directory/text/... -> string`、`number -> number`、`toggle -> boolean`、
  `select/preset -> string + enum`；`secret` 带 `writeOnly`。
- `mct schema --all --format openai`：可直接填入支持 function calling 的 Agent。
- `mct schema --all --format mcp`：可直接作为 MCP `tools/list` 的返回。
- `mct mcp`：stdio JSON-RPC，支持 `initialize`、`tools/list`、`tools/call`、`ping`、`shutdown`。

MCP 工具名会把 id 中的 `.` 等字符替换为 `_`（例如 `media.image-ocr` →
`media_image-ocr`），调用时用 `tools/call {name, arguments}`。


### 3.8 运行可观测性与跨进程调度

从当前 CLI 运行时起，`mct` 会自动把任务状态写到共享目录，GUI 每秒轮询，
所以在任务页能实时看到 CLI/MCP 发起的任务：

```text
$MCT_DATA_DIR/AgentJobs/<jobID>/
├── job.json          # 状态快照：status/progress/steps/artifacts/pid/error
├── events.jsonl      # Tool Protocol 事件流（控制台回放）
└── cancel.request    # GUI 或 mct jobs cancel 写入
```

- `job.json` 是**只读观察层**，真正的工作目录仍是 `Jobs/<jobID>`；
- `source` 会标记 `cli` / `mcp` / `batch` / `resume`；
- GUI 任务页「Agent / CLI 任务」可看进度、状态、步骤、产物，并可取消/打开目录；
- 进程崩溃后 GUI 会把超过 90s 没有 heartbeat 的活动任务显示为「可能已中断」；
  `mct jobs mark-interrupted` 可在命令行落盘标记。

**资源调度统一**

工具声明 `resources: ["gpu"]` 等之后，CLI/Agent 也会和 GUI 一样排队，而不是绕过调度器：

```text
Locks/<resource>-<slot>.lock   # fcntl 记录锁，Python 与 Swift 共用
```

- `gpu=1`、`network=2`、`cpu=核数-1`；
- `mct run` 在拿不到锁时状态为 `queued`，GUI 可见；
- 进程崩溃时内核自动释放锁；
- `--no-locks` 只用于调试，生产 Agent 不要使用；
- 批量任务逐个子任务抢锁；GPU 工具自动串行。

**取消**

- GUI「取消」或 `mct jobs cancel <id>` 会写 `cancel.request`；
- 执行进程在事件循环里轮询，收到后向子进程组发 `SIGTERM`；
- 资源等待阶段也会检查取消，不会卡在锁队列里；
- MCP 客户端发 `notifications/cancelled` 时走同一条取消链路，返回 `-32800`。

**MCP 完整能力**

`mct mcp` 现在提供：

- `tools/list` / `tools/call`（异步执行，不阻塞其他请求）；
- `notifications/progress`：请求带 `_meta.progressToken` 时按事件推送进度；
- `notifications/cancelled`：取消正在运行或排队中的工具；
- `resources/list` / `resources/templates/list` / `resources/read`：
  `mct://tools`、`mct://tools/{id}`、`mct://jobs`、`mct://jobs/{id}`、`mct://paths`；
- `resources/subscribe` / `unsubscribe`：任务变化推 `notifications/resources/updated`；
- `prompts/list` / `prompts/get`：`run_tool`、`review_job`、`debug_tool`；
- `notifications/message`：工具 `log` 事件转 MCP logging；
- `initialize` 声明 tools/resources/prompts/logging capabilities。

MCP 调用同样写 `AgentJobs`，因此 GUI 可以实时看到 MCP 发起的任务。

### 3.9 第三方工具加载与零源码验收

**加载方式（按优先级从高到低）**

| 方式 | 命令/位置 | 说明 |
|---|---|---|
| 显式目录 | `mct --tools-dir /path/Tools ...` | 最高优先级；适合测试/覆盖同名工具 |
| 环境变量 | `TOOLBOX_TOOLS_DIR=/path/Tools` | 次高；App 与 CLI 都识别 |
| 用户工具目录 | `$MCT_DATA_DIR/Tools` 或 `~/Library/Application Support/MacToolboxDemo/Tools` | 正式安装位置；同 id 覆盖内置 |
| 仓库/App 内置 | `Tools/` | 只读内置工具 |
| 官方安装命令 | `mct install <目录|tool.json|zip>` | 校验后复制到用户工具目录 |

同 id 时**后扫描到的覆盖先扫描到的**；因此显式目录和 `TOOLBOX_TOOLS_DIR`
可以覆盖内置/用户工具，适合开发测试。

```bash
# 安装（严格校验，要求 agent；旧工具加 --allow-legacy）
bin/mct install /tmp/my.toolbox --json
bin/mct install /tmp/my.toolbox.zip --force
bin/mct install /tmp/my.toolbox --into /tmp/test-tools

# 删除（默认只允许用户工具目录；--into 安装的用 --from 指定）
bin/mct uninstall my.tool --yes
bin/mct uninstall my.tool --from /tmp/test-tools --yes

# App 里加载：工具管理 → 重新扫描；或重启 App
```

**零源码验收流程（外部 AI / 第三方作者）**

不需要改 Swift、不需要把工具放进仓库 `Tools/`。按下面顺序验收：

```bash
# 1) 静态契约（只在有仓库时可用；外部作者可跳过）
python3 scripts/tool_lint.py /tmp/my.toolbox --strict
bin/mct validate /tmp/my.toolbox --strict

# 2) Agent 目录 / Schema
bin/mct --tools-dir /tmp/Tools describe my.tool --json
bin/mct --tools-dir /tmp/Tools schema my.tool

# 3) 环境与真实执行
bin/mct --tools-dir /tmp/Tools doctor my.tool --json
bin/mct --tools-dir /tmp/Tools run my.tool --input key=value --json

# 4) 安装到用户工具目录，再验证「不带 --tools-dir」也能发现
bin/mct install /tmp/my.toolbox --json
bin/mct list --json
bin/mct run my.tool --input key=value --json

# 5) App 扫描
MCT_DATA_DIR=/tmp/my-data ./dist/MacToolboxDemo.app/Contents/MacOS/MacToolboxDemo
# 工具管理 → 重新扫描；工具应出现在列表，且「工具问题」为空
```

验收通过的最低证据：

- `tool_lint --strict` / `mct validate --strict`：0 error；
- App Swift 扫描器：0 error，工具出现在列表；
- `mct describe` 有 `capability` + `inputSchema`；
- `mct doctor` 返回 `env.checks`，`healthy` 符合预期；
- `mct run` 返回 `ok=true`，产物路径真实存在；
- 安装到用户目录后，不传 `--tools-dir` 仍可 list/run；
- App 内能看到工具并运行一次（GUI 表单由 manifest 自动生成）。

**不需要改源码的部分**

- 表单、快速运行、批量、任务记录、AgentJobs 监控、MCP 工具目录、资源锁；
- `mct` 的 list/describe/schema/doctor/setup/run/batch/resume/jobs/install；
- App 扫描与校验。

**必须改源码的部分**

- 只有 `nativeView`（C 级定制 SwiftUI）工具需要改 Swift；
  按 [`原生工具开发指南.md`](原生工具开发指南.md) 的三处注册点执行。

## 4. Tool Protocol

Python/任何语言都行。约定：

- stdout：**每行一个 JSON 对象**；
- stderr：人类可读日志，App 原样显示为 `stderr`；
- stdin：人工检查点恢复时收到 `{"type":"continue","checkpoint":"..."}`；
- 取消：App 对进程组发 `SIGTERM`，宽限后 `SIGKILL`；脚本应让子进程也收到信号；
- 退出码 0 + `result.ok=true` 才算成功；非 0 失败。

### 4.1 事件

```json
{"type":"log","level":"info","message":"开始处理"}
{"type":"progress","fraction":0.4,"step":"encode","message":"40%"}
{"type":"step","step":"encode","title":"编码","state":"running"}
{"type":"step","step":"encode","title":"编码","state":"done"}
{"type":"artifact","id":"out","kind":"video","path":"/abs/out.mp4","label":"成品"}
{"type":"checkpoint","checkpoint":{"id":"review","title":"人工校对","message":"改完继续","artifacts":[...]}}
{"type":"result","ok":true,"summary":"完成","artifacts":[{"id":"out","kind":"video","path":"/abs/out.mp4"}]}
{"type":"error","code":"encode_failed","message":"编码失败","detail":"..."}
```

字段说明：

- `progress.fraction` 是 0–1；`step` 可选，但建议带。
- `artifact.id` 现在是稳定 id；`label` 会作为显示名（旧实现只看 `title`）。
- `result.artifacts` 里的每项是 `{id, kind, path, label?}`。
- `error` 的 `code/detail` 可选；`retryable` 当前不会被 App 使用。
- `hello` / `protocolVersion` 当前未实现，不要依赖握手。
- `env` 事件只用于 doctor：

```json
{"type":"env","checks":[
  {"id":"ffmpeg","label":"ffmpeg","status":"ok","detail":"6.1"},
  {"id":"model","label":"Whisper 模型","status":"fail","detail":"文件不存在","fixCommand":"...","fixable":true}
]}
```

`status` 用 `ok` / `warn` / `fail`；`fixable` 只影响展示。

**artifact 约定**

- `kind` 推荐使用：`text` / `json` / `image` / `video` / `audio` / `subtitle` /
  `report` / `file`；自定义 kind 可以工作，但 GUI 只会按通用文件展示。
- `id` 在同一任务内稳定且唯一，建议 `[A-Za-z0-9][A-Za-z0-9._-]*`，例如
  `statsJson` / `statsText` / `delivered`。
- `path` 必须是绝对路径（`mct` 会把相对路径按 jobDir 解析，但不要依赖这个兜底）。
- `result.artifacts` 应与之前的 `artifact` 事件一致；只写文件不发事件，GUI 不会登记产物。
- 工具自产 JSON 的时间字段建议 ISO 8601（UTC 用 `Z`）；协议本身不强制时间字段。
- 框架不规定同名产物覆盖策略；由工具在 `help` / README 说明，并优先使用
  「临时文件 + 原子替换」，避免半成品。
- 业务语义（行数口径、空值用省略还是 `null`、`outputDir` 是否自动创建、
  同名覆盖、时间格式）不属于框架契约，工具必须在 README 中写清楚。
  推荐：`outputDir` 自动创建、原子替换、ISO 8601；例如行数用「逻辑行，
  末尾无换行也算一行」并明确纯 CR/二进制行为。

**脚本退出码**

| 码 | 含义 |
|---|---|
| 0 | 成功（同时应发 `result.ok=true`） |
| 1 | 工具/IO 失败（发 `error`，或在 result 里 `ok=false`） |
| 2 | 配置/参数错误（可直接 stderr + 非 0） |
| 130 | 收到 SIGINT，清理后退出 |
| 143 | 收到 SIGTERM，清理后退出 |

`App` / `mct` 主要看 `result.ok` 和进程退出码；取消场景由外层状态覆盖，
但脚本仍应捕获 `SIGTERM`、清理临时文件并让子进程一起退出。

### 4.2 人工检查点

发出：

```json
{"type":"checkpoint","checkpoint":{
  "id":"review","title":"人工校对",
  "message":"修改 fixes.json 后继续",
  "artifacts":[{"id":"raw","kind":"text","path":"/abs/raw.txt"}]
}}
```

然后阻塞读 stdin。App 点「继续执行」会发：

```json
{"type":"continue","checkpoint":"review"}
```

收到后重新读文件、继续后续步骤。不要让 stdin 读到 EOF 就崩溃。

### 4.3 配置读取

`config.json` 是表单快照，另有：

```json
"_meta": {
  "toolID": "demo.echo",
  "toolVersion": "0.1.0",
  "toolDir": "/abs/toolbox",
  "jobDir": "/abs/job",
  "jobID": "...",
  "createdAt": "...",
  "fingerprint": "..."
}
```

约定：

- `secret` 字段在 config 里是空字符串；真实值通过 `MCT_SECRET_<key>` 环境变量传入。
- `_meta.jobDir` 是唯一可写工作区；工具包本身只读。
- 断点续跑时 `resume=true`；脚本应复用已有中间产物，指纹失效时 App 会从头跑。
  `mct resume --job <jobDir>` 也走同一约定；`mct` 会把 config 的 `resume` 改为 true。
- `outputDir` 不是框架保留字段，只是很多工具（含模板/字幕）自定义的输出目录约定。
- 批量时框架会写 `batch.input` 对应字段和 `outputDir`。

## 5. 批量

```json
"batch": {
  "title": "批量回显",
  "input": "file",
  "accept": ["txt", "md"],
  "skipExisting": true,
  "outputExtension": "txt"
}
```

- `input` 必须是已存在的 `file` 或 `directory` 字段。
- `accept` 不带点；目录扫描按扩展名过滤。
- `skipExisting` 为 true 时，框架用 `outputExtension`（或表单里的 `format`）判断
  同名输出是否已存在；两者都没有时不会跳过。
- 批量会把每个文件的路径写入 `batch.input` 字段，并统一写 `outputDir`。
- 批量子任务共享 `resources` 调度；GPU 工具请声明 `"resources":["gpu"]`。
- CLI/Agent 的 GPU/网络/CPU 容量与 GUI 共用同一批跨进程锁文件，不会绕过调度器。
- GUI 批量与 `mct batch` 使用同一套语义：
  `mct batch <id> --input <batch.input>=<dir|file> [--output-dir ...] [--skip-existing] [--jobs N]`。
  `--jobs` 只在工具没有 `gpu` 资源时生效；`skipExisting` 按 `format` 或
  `batch.outputExtension` 推断目标文件。

## 6. doctor / setup

`doctor` 用于「环境检测」；必须输出 `env` 事件，App 才能显示检查项：

```json
{"type":"env","checks":[{"id":"ffmpeg","label":"ffmpeg","status":"ok","detail":"6.1"}]}
{"type":"result","ok":true,"summary":"环境检测完成"}
```

`setup` 用于「环境修复」；可以输出 `log` / `env` / `result`，App 会展示日志。
没有外部依赖时可以不写 `setup`，或在脚本里直接返回 `result.ok=true`。

`doctor` 的语义：

- 命令结构与 `run` 相同：`{command, args}`，同样支持 `{{configFile}}` 等模板变量；
- 只要诊断流程正常完成，就发 `result.ok=true`；健康度由 `env.checks` 表达；
- 有 `fail` 检查项不等于 `result.ok=false`；`mct doctor --strict` 才会因 fail 返回 1；
- 如果诊断本身无法运行（例如脚本异常），才发 `result.ok=false` 或非 0 退出。

`setup` 的语义：

- 执行安装/下载/编译/修复，发 `log` / `env` / `result`；
- `result.ok=true` 表示修复成功；仍有缺失项时发 `ok=false`；
- 没有外部依赖时可以省略 `setup`，或返回一个说明“无需修复”的 `result.ok=true`。

`requirements` 只是说明，不会自动探测；不要以为写了 `ffmpeg` 就会自动检查。

CLI 侧：

```bash
bin/mct doctor <id> --json          # 聚合 env checks，返回 healthy
bin/mct doctor <id> --strict        # 有 fail 检查项时退出 1
bin/mct setup <id> --json           # 跑工具的 setup（安装/下载/编译等）
```

`mct doctor` / `mct setup` 都会建临时 jobDir、写 config、跑对应命令，并把
`env.checks` 汇总到最终 JSON 的 `checks` / `healthy`。
因此通过 `mct` 调用时 `_meta.jobDir` 一定存在；直接低层调用
`tool.py doctor/setup --config` 时必须自己传入包含 `_meta.jobDir` 的 config。

## 7. 密钥

```json
{"key":"apiKey","type":"secret","label":"API Key","help":"保存在 Keychain"}
```

- App 用 Keychain 存储，不写 `config.json` / `records.json`；
- 子进程环境变量：`MCT_SECRET_apiKey`；
- 脚本优先读环境变量，再回退 config：

```python
key = os.environ.get("MCT_SECRET_apiKey") or cfg.get("apiKey", "")
```

- 日志、产物、异常信息不要打印密钥。
- 不要新增 `secret` 文件落盘作为“缓存”。
- CLI / Agent 三种取值方式（优先级从高到低）：
  1. `--secret key=value`（只进子进程环境变量，不写 config）；
  2. 环境变量 `MCT_SECRET_key`；
  3. `mct` 自动读 macOS Keychain（service
     `com.chensinuo.mactoolbox.demo.secrets`，account `<toolID>.<key>`）。
  用 `--no-keychain` 可以禁用第 3 步，避免无头环境弹钥匙串授权。

## 8. 资源与并发

```json
"resources": ["gpu"]
```

- `gpu` 容量 1（whisper 等必须串行）；
- `network` 容量 2；
- `cpu` 容量 = 核数 - 1；
- 不声明 = 不占资源，可并发；
- 批量池只对非 GPU 任务并发；本地 GPU 批量仍串行。

## 9. 脚手架与校验

### 新建

```bash
python3 scripts/new_tool.py \
  --id demo.echo \
  --name "回显工具" \
  --category "示例" \
  --summary "把输入文本重复输出"
```

默认写入用户工具目录；`--tools-dir` 可改到仓库 `Tools/` 做内置工具。
`_template.toolbox` 自带可运行的 Python 脚本、doctor/setup、file/number/toggle/textarea 示例。

### 校验

```bash
python3 scripts/tool_lint.py Tools/demo.echo.toolbox
python3 scripts/tool_lint.py --all
python3 scripts/tool_lint.py --all --strict
python3 scripts/tool_lint.py --all --json
bin/mct validate --all --strict
```

- error 会阻断；warning 只提示；`--strict` 把缺失 `agent` 等 Agent 标准问题当 error。
- 会检查 JSON 结构、id、input 引用、select options、batch、presets、资源、
  `agent` 元数据、`{{toolDir}}` 引用和 `.py` 语法。
- 校验规则集中在 `scripts/toolbox_spec.py`，与 `mct validate`、MCP 共用，避免漂移。
- App 启动/重新扫描时也会做同样的语义校验；错误工具不会进入列表，
  在「工具管理 → 工具问题」里显示。

### Agent / CLI 自测（推荐）

```bash
# 1) 工具目录 + 能力描述
bin/mct list --json
bin/mct describe demo.echo --json

# 2) 输入 Schema / Agent 工具定义
bin/mct schema demo.echo
bin/mct schema --all --format openai

# 3) 环境检测
bin/mct doctor demo.echo --json

# 4) 真正运行（自动建 jobDir / config.json）
bin/mct run demo.echo --input text=hello --json

# 5) 批量（工具声明了 batch 时）
bin/mct batch media.image-ocr --input image=/tmp/images --output-dir /tmp/out

# 6) MCP（让支持 MCP 的 Agent 直接发现/调用）
bin/mct mcp
```

`mct run` 会自动：补默认值、应用 preset、校验 required/select/number/file、
创建 `Jobs/<时间>-<id>-<短id>/config.json`、注入 `MCT_SECRET_*`、解析 JSONL、
写 `mct-result.json`。工具作者不需要自己拼 config。

### 低层无头运行协议

```bash
python3 Tools/demo.echo.toolbox/scripts/tool.py run \
  --config /path/to/config.json
```

`config.json` 最小内容：

```json
{
  "text": "hello",
  "_meta": {
    "jobDir": "/tmp/demo-job",
    "toolDir": "/abs/demo.echo.toolbox"
  }
}
```

stdout 逐行看 JSON；这一步能过，App 和 `mct` 里基本就能跑。
但 Agent 应优先用 `mct run`，不要手写 `_meta` / secret / 指纹。

### App 内验证

1. 启动 App；
2. 工具管理 → 重新扫描；
3. 点新工具 → 填参数 → 开始运行；
4. 看控制台日志、步骤、产物；
5. 用批量/队列/断点各跑一次（如果工具声明了 batch/resources）。

开发时可用独立数据目录，避免污染自用数据：

```bash
MCT_DATA_DIR="$PWD/.demo-data" ./dist/MacToolboxDemo.app/Contents/MacOS/MacToolboxDemo
```

## 11. 常见错误

| 现象 | 原因 | 修复 |
|---|---|---|
| 工具不出现 | JSON 解析失败 / 校验 error / 目录名以 `_` 开头 | 看「工具问题」或 `tool_lint.py` |
| 表单为空 | 普通工具 `inputs` 为空或 key 重复；零输入工具空表单是预期 | 普通工具补 inputs；零输入工具确认 `run` 可不带参数 |
| 运行按钮无反应 | 必填字段为空 | 看红色提示；填 required 字段 |
| `mct` 找不到工具 | 工具不在搜索目录 / id 写错 | `mct paths` 看搜索顺序；`mct list --json` |
| `mct run` 报未知输入 | key 不在 inputs / 拼写错误 | `mct describe <id> --json` 查 inputSchema |
| `mct` 报文件不存在 | 传了相对路径 / batch 传了目录给 file 字段 | 用绝对路径；批量用 `mct batch` |
| Agent 看不到工具 | 缺 `agent` / `agent.enabled=false` | 补 agent；`mct list --agent-only` |
| MCP 工具名对不上 | id 被安全化（`.` → `_`） | `mct schema --all --format mcp` 看 name |
| 子进程拿不到 Key | 字段不是 `secret`，或脚本没读 `MCT_SECRET_*` | 改 type，读环境变量 |
| 批量不跳过 | 没有 `outputExtension` 且没有 `format` | 补 `batch.outputExtension` |
| 任务结束但无产物 | 只写了文件，没发 `artifact` | 发 artifact，或在 result.artifacts 里带 |
| `result` 事件丢失 | result.artifacts 里有 Path 等非 JSON 类型 | 只放 `{id,kind,path,label}` 字符串字典 |
| 中文乱码 | Python 没设置 UTF-8 | `sys.stdout.reconfigure(encoding="utf-8")`，App 已注入 `PYTHONIOENCODING` |
| 进度条不动 | 没发 `progress` 或 fraction 不是 0–1 | 按步骤发 progress |
| 取消后残留进程 | 脚本没把 SIGTERM 传给子进程 | 用进程组/信号处理；参考字幕工具 |
| 检查点后无法续跑 | 没读 `resume` / 没复用中间产物 | `cfg_bool(cfg,"resume")`；参考字幕工具 |
| 首次 OCR 很慢 | `swiftc` 正在编译 Vision 助手 | 缓存后秒开；`mct doctor media.image-ocr` 查看 |
