# 原生工具开发指南（nativeView / C 级）

本指南面向需要 **深度定制 SwiftUI 界面** 的工具。普通工具请先读
[`新工具开发指南.md`](新工具开发指南.md)；只有「表单 + 协议」无法表达交互时，
才升级为原生工具。

> 原生工具不是「绕过平台」的许可证。相反，原生工具必须同时满足：
> **GUI 可交互 + CLI/Agent 可调用 + 状态可观测 + 环境可诊断**。

---

## 1. 什么时候需要原生工具

适合：

- 需要拖拽画布、时间轴、预览、复杂表格、实时选择等定制 UI；
- 需要直接使用 AppKit / VisionKit / 系统窗口能力；
- 需要 App 内长期持有的状态（例如 Homebrew 操作控制台、OCR 结果编辑）。

不适合：

- 只是收参数、调 CLI、出文件 → 用普通 Protocol 工具；
- 只是给现有工具加一个参数 → 改 `tool.json`；
- 可以用通用表单 + `checkpoint` 表达的交互 → 不要新增原生页面。

判断标准：**如果新增功能需要改 `ToolDetailView` 或新增 SwiftUI 页面，才是原生工具。**

---

## 2. 硬性标准

原生工具的 `tool.json` 必须同时包含：

| 字段 | 要求 |
|---|---|
| `nativeView` | 必须是 `NativeToolKind` 的 rawValue，例如 `homebrew` / `imageOCR` |
| `inputs` | 至少用于 CLI/Agent 的输入；GUI 可以自行选择是否复用 |
| `run` | **必须有**，CLI/Agent 走 Tool Protocol |
| `doctor` | 建议有；返回 `env` 检查项 |
| `setup` | 有可安装/编译依赖时必须有 |
| `agent` | 必须声明 capability/checkpoint/timeoutSec/examples |
| `resources` | 真实占用 GPU/网络/CPU 时声明，GUI 与 CLI 共用跨进程锁 |

`nativeView` 只决定 GUI 怎么渲染，不替代 `run`。
`LoadedTool.isRunnable` 对原生工具仍为 `false`，所以 App 不会显示快速运行/批量入口；
CLI/Agent 用 `mct run <id>`，不要依赖 GUI 的 JobRunner。

## 3. 注册点（只改这三处 Swift）

### 3.1 新增 NativeToolKind

`Sources/ToolboxCore/NativeToolRegistry.swift`：

```swift
public enum NativeToolKind: String, CaseIterable, Sendable {
    case homebrew
    case imageOCR
    case pdfStudio          // 新增

    public var displayName: String {
        switch self {
        case .pdfStudio: return "PDF 工作台"
        // ...
        }
    }
}
```

校验器 `ToolValidation` 和详情路由都从这里取白名单，
**不要**再在其它地方写 `["homebrew", "imageOCR"]` 之类的字符串数组。

### 3.2 新增原生视图

`Sources/MacToolboxDemo/Views/PdfStudioView.swift`：

```swift
import AppKit
import SwiftUI
#if canImport(ToolboxCore)
import ToolboxCore
#endif

struct PdfStudioView: View {
    let tool: LoadedTool
    @StateObject private var controller = PdfStudioController()

    var body: some View {
        VStack(alignment: .leading, spacing: 16) {
            header
            // 自定义交互
        }
        .padding(28)
        .background(Color(nsColor: .windowBackgroundColor))
        .navigationTitle("")
        .onAppear { controller.loadFromEnvironmentIfNeeded() }
    }

    private var header: some View {
        HStack(spacing: 16) {
            ToolIconTile(tool: tool, size: 64)
            VStack(alignment: .leading, spacing: 4) {
                Text(tool.manifest.name)
                    .font(.system(size: 28, weight: .bold, design: .rounded))
                Text(tool.manifest.summary ?? "")
                    .foregroundStyle(.secondary)
            }
            Spacer()
        }
    }
}

@MainActor
private final class PdfStudioController: ObservableObject {
    @Published var isWorking = false
    @Published var errorMessage: String?
    private var task: Task<Void, Never>?
    private var token = UUID()

    func cancel() {
        task?.cancel()
        isWorking = false
    }
}
```

要求：

- 不要在 `body` 里做阻塞 I/O；
- 长任务用 `Task` + 取消 token，参考 `ImageOCRView`；
- 错误显示在界面上，不静默失败；
- 如果 GUI 需要参数，优先读取 `tool.manifest.inputs` / `AppModel.values(for:)`，
  避免再造一套配置模型。

### 3.3 在 ToolDetailView 路由

`Sources/MacToolboxDemo/Views/ToolDetailView.swift` 的 `nativeBody(_:)`：

```swift
@ViewBuilder
private func nativeBody(_ kind: NativeToolKind) -> some View {
    switch kind {
    case .homebrew:
        BrewManagerView()
            .environmentObject(model)
            .environmentObject(model.brewService)
    case .imageOCR:
        ImageOCRView(tool: tool)
    case .pdfStudio:
        PdfStudioView(tool: tool)
    }
}
```

如果新视图需要 `AppModel` 或服务，在这里注入，不要改全局路由。

## 4. CLI / Agent 侧

原生工具也必须提供 `scripts/tool.py`，支持：

```bash
python3 <tool>/scripts/tool.py run --config <config.json>
python3 <tool>/scripts/tool.py doctor --config <config.json>
python3 <tool>/scripts/tool.py setup --config <config.json>
```

- 遵循 Tool Protocol：stdout JSONL，stderr 人类日志；
- 读取 `config["_meta"]["jobDir"]` 作为唯一可写目录；
- secret 从 `MCT_SECRET_*` 读取；
- 发 `log/progress/step/artifact/result`；
- 接受 `SIGTERM` 并结束子进程组；
- 不要在 GUI 和 CLI 之间复制领域逻辑；复杂逻辑下沉到共享脚本。

推荐布局：

```text
Tools/pdf.studio.toolbox/
├── tool.json              # nativeView=pdfStudio + run/doctor/setup + agent
├── README.md
└── scripts/
    ├── tool.py            # CLI/Agent 入口
    └── core.py            # GUI 与 CLI 可复用的纯逻辑（可选）
```

GUI 侧如果也需要同一套逻辑，调用 `scripts/core.py`（通过 Process）
或把可共享算法放进 Swift 的独立类型；不要让 GUI 依赖 `tool.py` 的私有函数。

## 5. 测试清单（提交前）

```bash
# 1) 契约
python3 scripts/tool_lint.py Tools/pdf.studio.toolbox --strict
bin/mct validate --all --strict

# 2) 描述 / Schema / Agent 目录
bin/mct describe pdf.studio --json
bin/mct schema pdf.studio

# 3) 环境与 CLI
bin/mct doctor pdf.studio --json
bin/mct run pdf.studio --input ... --json

# 4) App 扫描（Swift 侧）
#    启动 App 后看「工具管理」是否有该工具、无工具问题
MCT_DATA_DIR="$PWD/.demo-data" ./dist/MacToolboxDemo.app/Contents/MacOS/MacToolboxDemo

# 5) 构建
./scripts/build_app.sh
```

原生工具特有检查：

- [ ] `ToolDetailView` 能进入自定义界面，不落入通用表单；
- [ ] 离开页面/取消任务后，后台 Task/子进程能停止；
- [ ] GUI 不写 `records.json` / `config.json`（除非明确需要）；
- [ ] CLI `mct run` 与 GUI 的核心行为一致，产物路径可解释；
- [ ] `mct doctor` 的 `env.checks` 覆盖 GUI 依赖的系统能力；
- [ ] `agent.examples` 至少有一个可执行示例；
- [ ] 如果工具声明 `resources`，CLI 任务在 GUI 中显示 `queued` 后再运行；
- [ ] 如果是长任务，AgentJobs 中出现状态（CLI 路径），GUI 可取消。

## 6. 现有原生工具参考

| 工具 | GUI | CLI | 说明 |
|---|---|---|---|
| `system.homebrew` | `BrewManagerView` | `scripts/tool.py` | 只读/修改操作分离，修改需 `allowMutations=true` |
| `media.image-ocr` | `ImageOCRView`（VisionKit） | `scripts/tool.py` + `ocr.swift`（Vision） | GUI 与 CLI 都走 macOS Vision，首次编译缓存 |

两者都验证了同一模式：

- `nativeView` 只负责 GUI；
- `run` + `agent` 负责 CLI/Agent；
- 后台任务写 `AgentJobs`，GUI 任务页可观察；
- 资源声明与普通工具完全一致。

---

## 7. 已知限制

- 原生工具仍需要改 Swift 源码（这是 C 级工具的代价），普通工具不需要；
- 原生 GUI 不会自动出现在「快速运行 / 批量 / 高级设置」入口；
- GUI 内部操作如果要被 Agent 观察，需要显式写 AgentJobs 或提供对应 CLI 命令；
- 原生工具的 UI 自动化测试目前仍以人工/截图为主，没有 XCTest UI target。
